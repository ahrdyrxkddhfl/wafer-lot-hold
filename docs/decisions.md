# 결정 기록

기술 선택과 버린 대안을 한두 줄씩 적는다.

## 0단계

- **모델 코드는 복사하지 않고 import한다.** 복사본이 원본과 어긋나면 가중치는 불러와지는데 판정만 틀어질 수 있다.
  노트북에만 있는 코드(pickle 호환 처리, 축소, 분할)는 import할 수 없어 출처 셀을 주석으로 적어 옮겼다.
- **분할은 원본 절차로 다시 만들고 기존 `split.npz`와 한 원소씩 비교한다.** 기존 파일에는 lotName이 없어서
  Lot 정보를 붙이려면 다시 만들어야 하고, 같은 분할임을 증명해야 12번 모델의 점수를 그대로 쓸 수 있다.
- **0단계에는 pytest를 두지 않는다.** 웨이퍼 저장소 가상환경에 pytest가 없고, 그 저장소는 수정하지 않는다.
  대신 검증 단계(해시, 분할 비교, 점수 재현)가 실패하면 exit 1로 멈추고 산출물을 쓰지 않는다.
- **산출물은 CPU 판정으로 만든다.** 다른 컴퓨터에서도 같은 결과가 나오게 하기 위해서다. 원래 점수는 MPS에서
  나왔으므로 MPS로도 판정해 비교한다(두 장치 예측 차이 0장).
- **웨이퍼 ID는 `{lotName}_W{waferIndex:02d}`.** Test 안에서 중복이 없음을 확인했다. 원본 추적용으로
  `src_row`(LSWMD.pkl 원본 행 위치)도 함께 남긴다.
- **정답 라벨은 판정 파일과 다른 파일·폴더(`evaluation/`)에 둔다.** 정답이 섞이면 AI 판정이 아니라 정답으로
  Lot을 멈추는 실수가 생길 수 있다.
- **정답 파일에 `label_source`(labeled/unlabeled)를 남긴다.** 원본 전처리가 라벨 없는 웨이퍼를 `none`으로 넣었기
  때문에, 평가 때 라벨 없음을 정상으로 치지 않고 따로 세기 위해서다.
- **웨이퍼 저장소 경로는 상대경로 기본값 + 환경변수 `WAFER_REPO`.** 절대경로는 계정 이름이 공개되고 다른 컴퓨터에서 맞지 않는다.
- **설정은 YAML(`pyyaml`).** 값마다 주석을 달 수 있고 웨이퍼 저장소 환경에 이미 있다. JSON은 주석을 달 수 없어 버렸다.

## 1단계

- **ORM과 마이그레이션 도구를 쓰지 않는다.** 잠금(`FOR UPDATE`)과 트랜잭션 범위가 SQL에 그대로 보이게 하기 위해서다.
  테이블 정의는 `schema.sql` 하나로 관리한다(버전이 하나뿐인 프로젝트).
- **연결은 autocommit으로 열고 함수 안에서 `with conn.transaction():`으로 트랜잭션을 연다.** 어디서 어디까지가
  한 트랜잭션인지 코드에서 바로 보인다. 바깥 트랜잭션 안에서 부르면 savepoint가 된다(psycopg 3 동작).
- **잠금이 정상 경로, 제약이 마지막 방어선.** 같은 Lot·같은 설비에 대한 요청은 행 잠금으로 줄 세워 깔끔한 규칙 오류로
  거절하고, 부분 유일 인덱스 등 제약은 잠금이 빠졌을 때를 대비한다. 제약 위반은 규칙 오류로 바꾸지 않고 그대로 실패시킨다
  (바꾸면 잠금이 빠져도 테스트가 통과해 잠금이 빠진 것을 알아챌 수 없다).
- **설비 잠금은 `FOR SHARE`가 아니라 `FOR UPDATE`.** `FOR SHARE`는 여러 트랜잭션이 동시에 잡을 수 있어 두 Lot이 같은 설비를
  함께 "비어 있음"으로 읽는다. 실제로 `FOR SHARE`로 바꾸면 I11 동시성 테스트가 실패했다.
- **잠그는 순서는 항상 Lot → 설비.** 순서가 섞이면 두 트랜잭션이 서로를 기다리는 교착이 생길 수 있다.
- **Hold 여부를 Lot 상태 값에 넣지 않는다.** 열린 Hold 행과 상태 값을 둘 다 두면 둘이 어긋날 수 있다.
- **재검사(RETEST)는 작업 지시를 새로 만들지 않고 `inspect_round`만 올린다.** 한 Lot은 한 공정을 한 번만 처리한다는
  제약(I2)을 유지하면서 같은 웨이퍼의 재판정을 다른 차수로 받기 위해서다.
- **폐기(I10)는 트리거 없이 서비스 검사로 막는다.** 이전 값과 비교하려면 트리거가 필요한데, 모든 변경이 Lot 잠금을 거치는
  서비스 함수로만 일어나므로 얻는 것에 비해 설명 부담이 크다.
- **테스트는 테스트 전용 DB에서 매 테스트 전에 TRUNCATE로 정리한다.** 동시성 테스트는 연결 두 개가 각자 커밋하므로
  롤백으로는 격리되지 않는다. 모든 테스트가 같은 방식을 쓰고, 끝이 아니라 시작 전에 비워 실패한 테스트의 데이터를 볼 수 있게 한다.
- **동시성 테스트는 행을 읽은 직후 0.3초 기다리게 해(monkeypatch) 경쟁 구간을 넓힌다.** 잠금이 없을 때 실패가
  우연이 아니라 매번 재현되게 하기 위해서다.
- **PostgreSQL 17.11로 고정(compose와 CI 같은 버전).** 18은 컨테이너 데이터 경로가 바뀌어 볼륨 설정이 달라진다.
- **python-dotenv로 `.env`를 읽는다.** 테스트와 스크립트가 셸에서 따로 export하지 않아도 같은 비밀번호를 쓴다.
